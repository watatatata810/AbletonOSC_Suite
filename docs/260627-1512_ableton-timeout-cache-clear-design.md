# Abletonタイムアウト時のサーバー側状態キャッシュクリア 設計仕様書

## 1. 目的と概要
Ableton Live との通信がタイムアウト（切断）した際、サーバー側に古いトラック再生情報やスロットのキャッシュが残り続けることで、再接続した際に重複処理防止ガード（`playingSlots[trackId] === slotIndex`）に引っかかり、フロントエンド（ブラウザ）へ音声ファイルのロード通知（`clip_playing` 等）が送信されず、波形がロードされない（数十秒待たされる）問題を修正します。

タイムアウト検知時に、サーバー側でもすべての再生情報キャッシュをクリーンアップし、再接続時に確実に波形再描画が即座に実行されるようにします。

---

## 2. 設計詳細

### 2.1 サーバー側の切断時クリーンアップ処理の追加
[packages/viewWaves/server.js](file:///c:/Users/watat/Documents/MySoftwares/AbletonOSC_Suite/packages/viewWaves/server.js)
- `setInterval` 内のタイムアウト監視ロジックにおいて、`abletonConnected` を `false` にして `numTracks = 0` にリセットする際、以下の状態キャッシュオブジェクトもすべて初期化（空に）します：
  - `playingSlots`: `{}` （各トラックの再生スロット位置キャッシュ）
  - `activeClips`: `{}` （再生中クリップキャッシュ）
  - `clipLengths`: `{}` （クリップ長およびマーカー位置等のキャッシュ）
- これにより、再接続時に Ableton から届く再生スロット情報が、初期値（`undefined`）と異なると判定され、重複ガードをスルーして正常に `clip_playing` がブラウザへ送信されます。

### 2.2 影響範囲とリスク
- **キャッシュの初期化**: タイムアウト（切断）時のみクリアするため、通常の演奏中の重複送信防止機能（スパム防止）には影響ありません。
- **再接続時のオーバーヘッド**: 接続復帰時にすべての情報（ファイルパス、長さ、マーカー位置等）を Ableton に再要求・デコードし直しますが、これはフロントエンド側の `resetAllTracksUI()` でUIが消去されているため、画面を元に戻すために必須の処理であり、意図通りの動作となります。

## 3. 検証計画
1. **切断復帰時の即時波形再描画テスト**:
   - アプリ起動中に `osc-router` のみを終了して意図的に「オレンジ明滅（疎通待ち）」に落とし、画面がクリアされることを確認します。
   - `osc-router` を再起動して疎通を復帰させた際、枠線が緑になると同時に、ブラウザの「Network」タブに `audio?path=...` の通信が即座に発生し、遅延なく波形が再描画されることを確認します。
