# AbletonOSC Suite ランチャーアプリ設計書 (Neutralinojs)

本ドキュメントは、AbletonOSC Suite 内の各パッケージ（ルーター、波形ビュワー、台本トリガー等）を一元的に起動・終了・状態管理するための、UI付きデスクトップアプリケーション（ランチャー）の設計仕様書です。

## 1. 目的と背景
現状、本スイートの各機能（`osc-router`, `viewWaves`, `DaihonTrigger` など）を起動するには、個別にコマンドラインやバッチファイルを実行する必要があり、管理が煩雑です。
本ランチャーアプリを導入することで、単一のUIからワンクリックで全パッケージの状態監視、起動・停止制御、およびモバイル端末（iPad等）からのアクセス情報取得を可能にし、ユーザー体験の向上と運用の安定化（ゾンビプロセスの防止など）を図ります。

---

## 2. 設計方針

1. **Neutralinojs の採用**
   * 軽量でリソース消費が少ないデスクトップアプリフレームワーク Neutralinojs を使用してランチャーを構築します。
2. **Node.js 拡張（Extension）によるプロセス制御（アプローチ1）**
   * Neutralinojs 自体のセキュリティ制約を回避し、強力なプロセス管理を行うため、バックグラウンドで常駐する Node.js プロセスを Extension として組み込みます。
   * Node.js の `child_process` を使用して各パッケージを制御します。
3. **ポカヨケ（Poka-Yoke）設計によるゾンビプロセス防止**
   * ランチャー終了時、起動したすべての子プロセスを自動でクリーンアップ（強制終了）し、バックグラウンドにプロセスが残るのを防止します。
4. **クロスプラットフォーム対応**
   * Windows だけでなく macOS 等の環境も考慮し、OS（`process.platform`）に応じて実行バイナリやキルコマンド、npmコマンドを動的に切り替えます。
   * バッチファイル（`.bat`）に依存しないプロセス起動を行います。
5. **iPad 等からのアクセシビリティ向上**
   * ホストPCのローカルIPアドレスを自動検知し、同一ネットワーク上のiPadなどからアクセスするためのURLおよびQRコードをUIに提供します。
6. **既存コードへの影響最小化**
   * 他のパッケージ（`viewWaves` や `DaihonTrigger` など）のコードを変更せず、ランチャー（`suite-launcher`）内だけで実装を完結させます。
7. **フラットなモダン・ダークモードデザイン**
   * ガラスモーフィズム（透過・ぼかし）は採用せず、くっきりとしたコントラストを持つソリッドでモダンなダークテーマUI（チャコールグレーと鮮やかなアクセントカラー）で構成します。

## 3. ディレクトリ構成

`packages/suite-launcher` パッケージを新規作成し、以下の構成とします。

```text
packages/
  └── suite-launcher/
      ├── neutralino.config.json    # Neutralinojs アプリ定義、拡張機能定義
      ├── package.json              # フロントエンド/ランチャー起動用の依存関係
      ├── run.js                    # 起動スクリプト (Neutralinoバイナリ起動用)
      ├── bin/                      # 各OS向け Neutralinojs バイナリ
      ├── resources/                # フロントエンドリソース
      │   ├── index.html            # メインUI画面 (HTML5)
      │   ├── css/
      │   │   └── main.css          # ソリッドなダークモードスタイル (Vanilla CSS)
      │   └── js/
      │       ├── neutralino.js     # Neutralino クライアントライブラリ
      │       └── main.js           # UIイベントハンドラ、拡張機能とのIPC通信
      └── extensions/
          └── launcher-service/     # バックグラウンドNode.js拡張機能
              ├── index.js          # プロセス管理、IP検出、QRコード生成ロジック
              └── package.json      # 拡張機能用の依存関係 (qrcode, tree-kill 等)
```

## 4. 機能詳細

### 4.1 プロセス起動・停止（OS判定による切り替え）
Node.js 拡張 (`launcher-service/index.js`) 内で、以下のOS判定に基づき適切なコマンドを実行します。

| 対象パッケージ | Windows での起動方法 | macOS / Linux での起動方法 |
| :--- | :--- | :--- |
| **一般Nodeアプリ** (`daihonTrigger` 等) | `npm.cmd run start --workspace=xxx` | `npm run start --workspace=xxx` |
| **波形ビュワー** (`viewWaves`) | `bin/neutralino-win_x64.exe --load-dir-res --path=.` を直接起動 | `bin/neutralino-mac_x64` などのOS用バイナリを直接起動 |

#### プロセス停止処理
* Windows では `taskkill /F /T /PID <pid>` を使用して子プロセスツリー全体を強制終了します。
* macOS/Linux では `process.kill(-pid, 'SIGKILL')`（マイナスPIDによるプロセスグループ全体の終了）またはクロスプラットフォーム対応の `tree-kill` ライブラリを使用して終了させます。

### 4.2 ローカルIPアドレスの取得とアクセスURLの表示
* Node.js の `os.networkInterfaces()` を呼び出し、現在アクティブなIPv4のプライベートIPアドレス（例: `192.168.X.X`）を動的に検出します。
* UI上には、iPad等からアクセスするための接続URLを表示します。
  * 例：`http://192.168.1.15:3001`
* UI上の「QRコード」ボタンをクリックすると、`qrcode` ライブラリを使用してデータURI（Base64画像）に変換されたQRコードがモーダルウィンドウで拡大表示されます。

### 4.3 状態監視
* `child_process` の `spawn` から返されるプロセスストリームを監視し、プロセスの起動成功（ポート監視または生存確認）および `exit`/`error` イベントを検知します。
* 状態変化を即座にランチャーUIへ通知し、インジケータ（起動中: 緑、停止中: 灰、エラー: 赤）を切り替えます。

## 5. UIデザイン仕様（フラット＆クリーン）

* **配色**:
  * 背景色: `#121212` (ソリッドな黒に近いダーク)
  * カード背景: `#1e1e1e` (やや明るいグレー)
  * ボーダー: `#333333` (境界を明示)
  * テキスト: `#e0e0e0` (可読性の高いオフホワイト)
  * プライマリ/アクセント: `#007acc` (リンク/ボタン青), `#4caf50` (稼働緑), `#f44336` (停止/エラー赤)
* **構成**:
  * **Header**: タイトル、PCのローカルIP、一括「全起動」「全停止」ボタン
  * **Cards (Grid)**: パッケージごとの制御パネル
    * パッケージ名、ステータスバッジ
    * アクションボタン（起動/停止）
    * 接続URL（Local / IP）
    * QRコード表示ボタン（モーダルで表示）
  * **Console**: 実行ログを表示するスクロール可能なログエリア（開閉式）

## 6. 検証計画

### 6.1 自動・手動テスト項目
1. **ランチャー起動確認**: アプリ起動時にエラーなくウィンドウが開き、ローカルIPアドレスが正しく検知・表示されること。
2. **個別起動・停止テスト**: 各パッケージの「起動」を押した際、対応するプロセスが立ち上がり、「停止」でクリーンに終了すること。
3. **波形ビュワー単体起動**: `viewWaves` の「起動」を押した際、外部ブラウザではなく専用の Neutralino ウィンドウが現状と同じように開くこと。
4. **外部接続テスト**: iPad等からランチャーに表示されたIP/QRコードを使って `DaihonTrigger` 等のWeb画面に正常にアクセスできること。
5. **ポカヨケテスト**: ランチャーを閉じた際、バックグラウンドに `node.exe` などの残存プロセスがないこと。
