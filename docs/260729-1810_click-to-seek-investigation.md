# 波形クリックでシーク機能の調査結果（見送り）

**調査日**: 2026-07-29
**結論**: **見送り**。AbletonOSC 側の制約により、非破壊で実現できる精度が「1小節単位」に留まるため。
**対象だった機能**: viewWaves の波形をクリックした位置から再生を開始する（右上の隠しメニューでオン/オフ）

このドキュメントは、再検討する際に**同じ調査をやり直さないため**の記録です（調査には Live の再生位置を実際に飛ばす必要があり、気軽に繰り返せません）。

---

## AbletonOSC の API 制約

`Remote Scripts/AbletonOSC/abletonosc/clip.py` を確認した結果:

- **`playing_position` は読み取り専用**（`properties_r` に定義）。`/live/clip/set/playing_position` は**存在しない**
- 書き込み可能なのは `start_marker` / `loop_start` / `loop_end` / `position` / `looping` など（`properties_rw`）
- `song.py` のメソッドに `jump_by` / `start_playing` / `continue_playing` などがある（`/live/song/<method>`）

つまり「このクリップをこの位置から再生」を直接指定する手段は無い。

## `/live/song/jump_by` の実測（Ableton Live 12・セッションビュー再生中）

| 送った値 | 結果 |
|---|---|
| `8`（2小節） | ✅ ちょうど +8拍 移動 |
| `4`（1小節） | ✅ ちょうど +3.999拍 移動 |
| `3.37` | ❌ 無反応 |
| `1.5` | ❌ 無反応 |
| `1`（1拍） | ❌ 無反応 |

**セッションビューのクリップにも効く**が、移動単位は**小節**。4の倍数だけが通り、それ未満は0に切り捨てられる挙動と全データが一致する（`floor(値 ÷ 4)` 小節ぶん移動）。

〈仮説・未検証〉Live のグローバルクオンタイズ設定（おそらく「1 Bar」）に従っている。検証には Live 上部のクオンタイズ設定の変更が必要で、これはシーン発火のタイミングにも影響する重要な設定のため未実施。

なお `jump_by` は `Song` のメソッドなのでトラック指定の引数が無く、**必然的にグローバル**（再生中の全トラックが同じ量だけ動く）。

## 検討した2案とトレードオフ

| 案 | 精度 | 副作用 |
|---|---|---|
| A: `jump_by` | 1小節単位（120BPM 4/4 で2秒刻み） | 非破壊。ただし全トラックが一緒に動く |
| B: `start_marker` を書き換えて `fire` | サンプル精度 | **プロジェクトを書き換える**（マーカー移動・Undo履歴・保存に残る） |

**A と B は「クリップ単位の正確なシーク」と「プロジェクトを壊さないこと」のトレードオフ**であり、両立しない。ライブ本番用ツールという性格上 B は方針と逆を向くため、実質 A のみが候補だったが、2秒刻みでは期待した機能にならないと判断した。

## UI 側の下調べ（実装する場合に必要な情報）

- 現在 WaveSurfer は `interact: false`（`wsOptions`）でクリックによるシークを無効化している
- 波形の重なり順: 背景 → WebGLの転送先canvas（`pointer-events: none`）→ WaveSurferレイヤー（`z-index: 2`、**ここがクリックを受ける**）→ マーカーのグレーアウト（`z-index: 5`、`pointer-events: none`）
- 隠しメニュー（`#settings-panel`）は右上20pxのホバーで開く。既存項目は 強制同期ボタン / ラグ補正スライダー / 時計トグル / バッジトグル

## 再検討する条件

- AbletonOSC が `playing_position` の書き込みに対応したとき
- グローバルクオンタイズを細かく（1/4 や None に）できる運用になり、`jump_by` の精度が上がることを確認できたとき
- リハーサル専用など、プロジェクトの書き換え（B案）が許容できる用途が明確になったとき
