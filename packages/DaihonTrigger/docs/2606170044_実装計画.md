# 台本連携ポン出しアプリ（Ableton Live OSC）実装計画

本計画は、PDFの台本を表示し、手書きの注釈を書き込みつつ、Ableton LiveのBGMや効果音を直接トリガーできる「インタラクティブ台本ポン出しアプリ」の開発プランです。

**★アップデート**: 同一ネットワーク上のiPadやAndroidタブレットのブラウザからもアクセス・操作できるよう、Webサーバーアーキテクチャを採用します。

---

## 🎯 プロジェクト概要 (Goal Description)

**目的**: 演劇、配信、ライブパフォーマンス等において、PDFの台本とAbleton Liveの再生制御を統合し、シームレスで直感的な「ポン出し」環境を構築する。

**主な機能**:
1. PDF台本の表示とページ送り
2. ペンや指による手書き注釈（ハイライト、文字書き込み）機能
3. 台本上に直接配置・タップできる「Abletonクリップトリガー」ボタン
4. それらデータの永続化（保存・復元）
5. **【New】iPad/Androidタブレット等、同一LAN内の端末からのブラウザアクセスと操作**

---

## 🛠️ 技術スタック (Technology Stack)

タブレットからのアクセスを前提とするため、ローカルでWebサーバーを立ち上げる構成に変更します。

- **バックエンド**: `Node.js` + `Express` (Webサーバー兼API)
- **双方向通信**: `Socket.IO` または標準 `WebSocket` (ブラウザ - Node.js間のリアルタイム通信)
- **OSC通信**: `node-osc` (Node.js - Ableton間の通信)
- **フロントエンド**: HTML / CSS / Vanilla JavaScript (または軽量なフレームワーク)
- **PDF描画エンジン**: `PDF.js` (Mozilla製。PDFをHTMLのCanvasとして描画)
- **手書き＆ボタン配置**: `Fabric.js` (Canvas上の描画、オブジェクト配置、保存・復元。**タッチイベント対応**)

---

## 🏗️ システムアーキテクチャ設計 (Architecture)

### 1. ネットワーク構成 (LAN対応)
- **ホストPC (Ableton起動PC)**: Node.jsサーバーを起動。IPアドレス `0.0.0.0` (すべてのネットワークインターフェース) で待機します。
- **タブレット (iPad/Android)**: ホストPCのローカルIPアドレス（例: `http://192.168.1.15:3000`）にブラウザでアクセスし、UIを操作します。ホストPC上のブラウザで開くことも可能です。

### 2. 描画レイヤー構造 (フロントエンド)
- **Layer 1 (最背面)**: `PDF.js` によって描画された現在の台本ページ（画像としてのCanvas）。
- **Layer 2 (前面)**: `Fabric.js` によるインタラクティブCanvas。ここに「手書きの線」や「配置されたトリガーボタン」が乗ります。タッチ操作（スワイプ、ピンチズーム等）を前提としたUI設計を行います。

### 3. データ保存の仕組み
台本への書き込みやボタンの配置データは、ページごとにJSON形式で保存します。
フロントエンドからNode.jsサーバーへ保存APIを叩き、ホストPC上の `project_data.json` 等に保存・管理します。タブレット側にはデータを持たせず、常にサーバーと同期します。

### 4. OSC通信フロー
1. タブレット上のボタンをタップ
2. WebSocket経由で Node.js サーバーへ発火命令を送信
3. Node.js サーバーからローカルの Ableton Live へ `node-osc` でパケット（例: `/live/clip/fire 1 3`）を送信

## 📝 実装フェーズ (Implementation Steps)

### フェーズ1：基礎基盤の構築 (LANサーバー)
- [ ] Node.js + Express プロジェクトを初期化する。
- [ ] 静的ファイル（HTML/JS）を配信し、`0.0.0.0` で待ち受けるサーバーを構築。
- [ ] 起動時に「アクセス用URL (例: `http://192.168.x.x:3000`)」をコンソール画面に表示する機能を実装。
- [ ] AbletonOSCと通信し、クリップを発火できるかテストする。

### フェーズ2：PDF表示機能の組み込み (フロントエンド)
- [ ] `PDF.js` を導入し、サーバー上のPDFファイルを読み込んでCanvasに描画する。
- [ ] iPad/Androidのタッチ操作で「次へ」「前へ」のページ送りができるようにする。

### フェーズ3：手書き＆オブジェクト配置機能 (Fabric.js)
- [ ] `Fabric.js` を導入し、PDFの上に描画モードを追加する。**指やApple Pencil等での書き込み（Touchイベント）を最適化**する。
- [ ] 画面を長押しまたは専用メニューから「OSCトリガーボタン」を配置できるようにする。
- [ ] 各トリガーに「トラック番号」「シーン番号」を持たせるUIを作成する（タブレット上で入力しやすいUI）。

### フェーズ4：連携とデータ保存
- [ ] トリガーボタンをタップした際に、WebSocket経由でサーバーへ通信し、Abletonが反応するよう連携する。
- [ ] 手書きデータとボタン情報をサーバー上にJSONとして保存し、再読み込み時やページめくり時に復元するシステムを作る。

## ✅ 確定した仕様 (Decision Log / 2026-06-17)

Brainstormingにより、初期リリース（MVP）に向けて以下の仕様が確定しました。

1. **ホストPC側でのアプリ画面（専用ウィンドウ）**:
   * **決定**: 不要。タブレットのブラウザからのアクセスのみで完結させる。
   * **理由**: ホストPCにはAbleton Liveの画面を全画面表示しておくため。
2. **マルチデバイスの同期**:
   * **決定**: 初期リリースでの実装は見送る。ただし、将来的な追加を見越してWebSocketの基礎設計は拡張性を持たせておく。
3. **PDFの読み込みと管理**:
   * **決定**: ホストPCの特定フォルダ（例: `public/pdfs/`）にPDFファイルを手動で配置し、それを読み込むシンプルな方式（アプローチA）を採用する。
   * **理由**: コア機能（表示・手書き・OSC発火）の開発・テストを最速で行うため。将来的にタブレットからのアップロード機能を追加する。
