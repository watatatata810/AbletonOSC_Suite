# Liveセッションビュー連携・グリッド選択機能 実装計画

Ableton Liveのセッションビュー情報を取得し、タブレット上でクリップやシーンを視覚的（グリッド式）に選択してトリガーボタンを配置できる機能を追加します。

## 🎯 目標 (Goal)
- Ableton Live上のトラック名、シーン名、クリップ名をアプリ（Node.js）経由で取得する。
- トリガー配置モードで、Liveのセッションビューを模したグリッド状の選択UI（モーダル）を表示する。
- 選択したクリップ名（またはシーン名）を、Fabric.jsのボタンのテキストとして表示する。

## ❓ ユーザーへの確認事項 (Open Questions)

> [!IMPORTANT]
> 波形ビューアーアプリとの「OSCポート競合」に関する解決策の確認事項です。

1. **OSCルーター（中継アプリ）の導入方法について**
   調査の結果、解決策B（汎用的な独立したOSCルーターを挟む）には、主に以下の2つのアプローチがあります。どちらが運用しやすいでしょうか？

   - **アプローチ1: 既存のルーティングソフトを使う**
     「**OSCRouter** (ETCLabs製)」や「**Chataigne**」といった無料の汎用ツールをインストールし、GUIで「11001で受信し、11002と11003へ転送する」設定を行います。
     （メリット: 設定が視覚的で分かりやすく、他ソフトとの連携など拡張性が高い）
   
   - **アプローチ2: シンプルなNode.jsスクリプトを自作する（推奨）**
     本プロジェクト内に `osc-router.js` のような20行程度の小さなプログラムを追加し、当アプリを立ち上げる前に（または同時に）実行します。
     （メリット: 新しいソフトのインストールが不要で、環境依存が少ないため開発・運用が最もスムーズです）

2. **データの同期タイミングについて**
   ご要望通り、**「配置モードを開くたびに毎回Liveへ問い合わせる」**仕様で実装します。（※決定事項）

## 🛠 提案する変更内容 (Proposed Changes)

### 1. サーバー側（OSC通信の拡張）
- **`server.js`**
  - 新たなOSC受信サーバー（例: ポート11002）を立ち上げる。
  - フロントエンドからの `get_session_data` リクエストを受け取り、AbletonOSCに向けて `/live/song/get/num_tracks` などの一連のクエリを発行する。
  - Abletonからの返答を収集し、二次元配列（グリッドデータ）に整形してフロントエンドへ返す。

### 2. フロントエンド側（グリッドUIの構築）
- **`public/index.html`**
  - 現在のシンプルな「番号入力モーダル」を廃止し、セッションビュー風の「グリッド選択モーダル」を新たに構築する。
- **`public/style.css`**
  - CSS Gridなどを活用し、列（トラック）と行（シーン）が交差するマトリックス状のデザインを作成する。
- **`public/app.js`**
  - `[Liveから取得]` ボタンを追加し、サーバーへデータ取得リクエストを送るロジックを実装。
  - グリッドのセルをタップした際に、そのセルの情報（トラック番号、シーン番号、クリップ名）を取得して Fabric.js のボタンを生成する処理を実装。ボタンのラベルを「クリップ名（またはシーン名）」にする。

## 🧪 検証計画 (Verification Plan)
1. **OSCポートの共存テスト**: 新しいポートでAbletonからトラック名などの返答が正しく返ってくるかログを確認する。
2. **グリッド描画テスト**: Ableton上のセッションビューと、タブレット上のグリッドUIが一致しているか目視で確認する。
3. **配置テスト**: グリッドから選択して配置したボタンに正しい名前が入り、タップで対象のクリップが発火するか確認する。
